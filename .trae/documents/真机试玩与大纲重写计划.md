# 真机试玩验证 + 游戏大纲重写 计划

## 1. 概要（Summary）

两件事，按顺序执行：

1. **真机验证**：给游戏加一个轻量试玩日志（每关结束自动写一行 CSV，零操作负担），用户启动 `python main.py` 玩 10+ 局；玩完后我读取日志做数据分析（通关率、死亡原因、关卡留存、单局时长），回答「是否还想再来一局」背后的真实问题。
2. **再写游戏大纲（近期待落地版）**：基于试玩数据重写 `docs/GDD.md`，补全五个维度——关卡（第 4、5 关设计 + 难度校准）、成长系统（局内道具 + 局间星级评价，明确不做存档/升级树）、UI 流程、美术风格扩展规则、音效需求清单；并给出下一个里程碑 M5 的定义。

原则：日志功能不侵入训练管线（AI 训练/评估不写日志）；大纲只写下一轮能落地的东西，不写远期愿景。

## 3. 提议改动（Proposed Changes）

### 3.1 试玩日志（代码，本次实现）

**新建 `game/playtest.py`**（约 50 行）

- 常量：`LOG_DIR = "playtest"`、`LOG_FILE = "playtest/sessions.csv"`（首次写入时自动 `os.makedirs`）。
- 表头（每关一行）：
  `session, ts, level, result, lose_reason, run_complete, score, kills, level_kills, lives_left, time_sec, pickups_taken`
  - `session`：每次 `start_game()` 生成的时间戳 ID（精确到秒），区分 10 局。
  - `result`：`win / lose`；`lose_reason`：`life / base / ""`。
  - `run_complete`：本关胜利且是最后一关。
  - `time_sec`：本关用时（秒，保留 1 位）；`pickups_taken`：本关拾取道具数。
- 提供 `PlaytestLogger`：`start_session()` / `record_level(game)`；内部用 `csv` 追加写并立即 `flush`（防崩溃丢数据）。

**改 `game/core.py`**（约 25 行增量）

- `Game.__init__(self, log_playtest=False)`：默认关闭；开启时创建 `PlaytestLogger`。
- `_reset_battle()`：新增 `self.pickups_taken = 0`（按关清零，与 `level_kills` 同节奏）；`_apply_pickup()` 内 `+1`。
- `start_game()`：若 logger 存在 → `logger.start_session()`。
- `_end(win)`：若 logger 存在 → `logger.record_level(self)`（此时 score/lives 已含通关奖励，正好是要记录的值）。

**改 `main.py`**（1 行）：`Game()` → `Game(log_playtest=True)`。

**不改**：`env.py`、`play_ai.py`、`train.py`、`evaluate.py`（默认 `log_playtest=False`，零影响）；`settings.py` 不加常量。

**README.md** 追加 4 行小节「试玩日志」：位置、字段含义、如何清空。

### 3.2 真机试玩执行（用户操作 + 我分析）

1. 用户运行 `python main.py`，正常玩 10 局以上（建议刻意输几局、打到第 3 关，让死亡原因有分布）。
2. 我读 `playtest/sessions.csv` 输出分析（直接在回复里给，不落文件）：
   - 每关通过率、到达关卡漏斗（10 局里几局见到第 2/3 关）；
   - 失败原因分布（生命耗尽 vs 基地被毁）；
   - 单局/单关时长分布，对照 GDD 的 1.5~2.5min 锚点；
   - 道具拾取率（掉了但没吃 = 引导不足的信号）。
3. 给出「想不想再来一局」的判断结论与 2~3 个具体调优建议（数值级，如出生保护、突击型比例）。

## 4. 关键假设与决策（Assumptions & Decisions）

1. 试玩日志按"每关一行"而非"每局一行"：死亡原因和关卡漏斗都需要关级粒度。
2. 日志开关默认关、只在 `main.py` 打开：保证 RL 管线与回放行为完全不变。
3. 成长系统选型为星级评价：是"近期待落地"约束下唯一不引入存档/数值膨胀的成长形式；火力道具已覆盖局内成长。
4. 大纲直接改 `docs/GDD.md` 升 v1.1，不另开文件：保持单一事实来源，旧版内容（数值表、AI 章节）原样保留。
5. 试玩分析只出结论与建议，不改数值——是否调参由用户看数据后决定。
