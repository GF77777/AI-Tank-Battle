# 蓄力炮机制（对标氮气）计划

## 1. 概要

为玩家坦克增加「蓄力炮」：**按住空格蓄力 ≥0.75 秒，松开发出穿甲弹**——穿透砖墙（顺带摧毁）、可连续击杀多个敌人，只被钢板/边界挡下。代价是**蓄力期间不能移动**（允许转向瞄准），且穿甲弹发射后冷却翻倍（42 帧）。轻点空格仍是普通弹，手感完全不变。

设计定位：对标赛车氮气/漂移的"风险换收益"——站桩 0.75 秒换一发高爆发，用来打一串敌人、快速开路、或抢时间救基地。**AI 环境完全不用蓄力机制**，训练/评估语义逐位不变。

## 3. 提议改动

### 3.1 `game/settings.py`（新增 2 个常量）

```python
PLAYER_CHARGE_FRAMES = 45        # 蓄力满所需帧数（0.75s）
PLAYER_CHARGE_COOLDOWN = 42      # 穿甲弹发射后的冷却（2×普通）
```

### 3.2 `game/entities.py`（2 处）

- `Bullet.__init__` 增加参数 `piercing=False`，存 `self.piercing`。
- `Tank.make_bullet(piercing=False)`：透传给 `Bullet(...)`。

### 3.3 `game/core.py`（核心）

1. `_reset_battle()`：`self.charging = False; self.charge_frames = 0`。
2. `update()`：玩家段改为蓄力感知——
   ```python
   if self.charging:
       self.charge_frames += 1
       if input_dir is not None:
           self.player.set_direction(input_dir)   # 蓄力中允许转向瞄准，禁止移动
   elif input_dir is not None:
       self.player.set_direction(input_dir)
       self.move_tank(self.player)
   ```
3. 新增两个方法（人类模式专用入口）：
   - `start_charge()`：仅 PLAYING 且玩家存活、冷却就绪、弹数未满时进入蓄力（`self.charging=True; self.charge_frames=0`）。
   - `release_fire()`：退出蓄力；`charge_frames >= PLAYER_CHARGE_FRAMES` → 穿甲弹，否则普通弹。
4. `player_fire(piercing=False)`：透传穿透标志；穿甲弹发射后覆盖 `self.player.fire_cooldown = S.PLAYER_CHARGE_COOLDOWN`。AI 路径不传参，行为不变。
5. 穿透碰撞：
   - `_bullet_vs_tiles`：砖墙分支 `hit = hit or not bullet.piercing`（穿透弹毁砖但继续飞）；钢板/基地逻辑不变（钢挡弹消、玩家弹仍不毁基地）。
   - 玩家弹 vs 敌人：穿透弹命中不置 `b.alive=False`、不 `break`（可连杀）；无敌出生保护的敌人对两种弹都只挡普通弹、穿透弹直接穿过不掉血（`if e.invincible <= 0: 击杀` 且 `if not b.piercing: b.alive=False; break`）。
6. 蓄力打断：`_on_player_hit()` 玩家死亡分支里 `self.charging=False`；`_reset_battle` 已覆盖换关/重开。
7. 渲染：`_render_field()` 画完玩家后，若 `self.charging` 在玩家头顶画蓄力条（28×4 深灰底，按 `charge_frames/PLAYER_CHARGE_FRAMES` 比例填充，黄色、蓄满变红）；穿透弹用新精灵绘制。

### 3.4 `game/sprites.py`

新增 `self.bullet_piercing`：`_BULLET` 矩阵换黄色系调色板后 `scale` 到 8×8（比普通弹 6×6 略大略亮）；绘制时以 `b.rect.center` 居中 blit。

### 3.5 `main.py`

- 事件循环：`KEYDOWN(K_SPACE)` → `game.start_charge()`；`KEYUP(K_SPACE)` → `game.release_fire()`。
- 每帧兜底：`if game.charging and not keys[pygame.K_SPACE]: game.release_fire()`（防窗口失焦导致卡蓄力）。
- `game.update()` 不再传 `input_fire`（默认 False）。

### 3.6 文档（各 1~3 行）

- README 操作表加「按住空格蓄力≥0.75s 松开发出穿甲弹（穿砖穿人，被钢板挡）；蓄力中不能移动」。
- GDD 升 v1.3：变更记录加蓄力炮；第 5 章规则或第 7 章后补「蓄力炮」小节（机制 + 数值 + 人类专属说明）。
- UI 规范补蓄力条规格（玩家头顶 28×4，黄→红）。

## 4. 关键假设与决策

1. **AI 不学蓄力**：env 的 `update(input_fire)` 保持瞬时普通弹语义，`start_charge/release_fire` 只被 main.py 调用——训练环境零变化，基线评估可直接复用。AI 侧蓄力留作 M4+ 可选。
2. 蓄力中**允许转向**：站桩但能瞄准，是"炮塔"手感；禁止移动是核心代价，不动摇。
3. 穿透弹对**无敌敌人穿过不掉血**：避免"蓄力一发白打"的负反馈。
4. 穿甲弹**不**提升移动/子弹速度、不增加弹数上限：平衡来源只有站桩风险与双倍冷却。
5. 穿透弹与「火力」道具不叠加特殊规则（火力只影响普通冷却与弹数，已有逻辑自然兼容）。

## 5. 验证方案

| 验证项 | 方法 | 通过标准 |
|---|---|---|
| 蓄力档位 | headless：轻点（charge<45）与蓄满（≥45）分别 release | 前者普通弹、后者 `piercing=True` |
| 穿透规则 | 构造直线上两敌 + 砖墙 + 钢板场景 | 穿甲弹连杀两敌、毁砖不停、被钢板挡下；玩家弹仍不毁基地 |
| 蓄力约束 | 蓄力中传入移动方向 | 坐标不变、朝向可变 |
| 蓄力打断 | 蓄力中打死玩家 | `charging=False`，复活后可重新蓄力 |
| 打断兜底 | main.py 编译 + 失焦兜底逻辑存在 | 代码审查 + 事件序列无异常 |
| AI 回归 | `evaluate.py --episodes 3 --seed 1` | 胜率 0% / 平均击杀 0.0 与基线完全一致 |
| 渲染 | headless 蓄力中渲染 + 穿甲弹绘制 | 无异常 |
