## 3. 本轮交付：两份设计文档（具体章节已定死）

### 3.1 新建 `docs/GDD.md`（游戏大纲 / 游戏策划）

目录与必填内容：

1. **一句话定位**：用上文那句；附"目标玩家 / 平台 / 单局时长 / 难度曲线"。
2. **核心体验三条**：①一气呵成的走位射击手感 ②守基地的紧张博弈 ③"这是我训出来的 AI"。
3. **核心循环**：进关 → 走位/射击/吃道具 → 清敌 → 结算 → 下一关（含死亡复活支线）。
4. **操作与手感参数表**：移动 2px/帧、敌速 1px/帧、子弹 5px/帧、射速 0.35s、玩家弹上限 2、敌方弹上限 4、无敌 2s、4px 网格对齐——**全部取自 [settings.py](file:///c:/Users/CJP/Desktop/AI坦克大战/game/settings.py) 现有常量，不新增数值**。
5. **敌型设计（2 种，MVP 只做 1 种，新增 1 种）**：
   * 基础型（现有）：随机直行 + 偏向向下，1 发摧毁。
   * 突击型（新增）：速度 ×1.6，优先朝玩家方向转向，1 发摧毁 —— 用最小实现制造节奏变化。
   * 明确"不做"：护甲型/炮台型（超出范围）。
6. **道具设计（3 种，落地即可）**：护盾（5s 无敌）、火力（子弹+1 上限且射速×0.7，15s）、清屏（立即清全场敌人，仅掉落 1 次/关）。写明掉落规则：每关击杀第 3/6/9 辆时各掉 1 个，位置随机在空地。
7. **关卡节奏（3 关）**：第 1 关教学（开阔、砖墙多、敌人 10）；第 2 关河流/林地割裂（敌人 12）；第 3 关钢板要塞（敌人 14，基地双层保护）。给每关的"预期首通率"与"预期用时"作为调参锚点。
8. **难度与数值不变量**：3 命、基地 1 血、击杀 +100 分、通关 +500 分（分值与 RL 奖励解耦，明确写清"游戏分数"与"训练奖励"是两套数值）。
9. **AI 系统说明（答辩核心章节）**：观测量 248 维各段含义、10 动作、Double DQN 结构、奖励表、训练时长、**真实评估结果（0% 胜率 / 0～3.2 击杀）**、已知局限与改进方向（奖励塑形、优先经验回放）。
10. **美术与音效基调**：FC 复古像素、四色调色板、音效全部用代码合成（无外部素材）。
11. **不做清单**：存档、商店、成就、联网、移动端、双人合作 —— 与需求文档「暂不做」一致。

### 3.2 新建 `docs/UI设计规范.md`（UI 设计）

目录与必填内容：

1. **界面清单与状态流转**：`标题 → 模式选择（闯关 / 观战AI / 训练曲线）→ 游戏(HUD) → 暂停 → 结算(胜利/失败) → 标题`，画一张状态机图（文本箭头即可）。
2. **统一视觉基线（新增 `settings.py` 常量）**：
   * 像素网格：所有 UI 元素对齐 8px；窗口逻辑分辨率 416×464，2 倍显示。
   * 调色板：主背景 `#181820`、主强调 `#F0C83C`（玩家黄）、危险 `#DC3228`（红）、成功 `#50C850`（绿）、文字 `#FFFFFF`、次级文字 `#909090`。
   * 字号：标题 40 / 大标题 28 / 正文 20 / 小字 14（复用现有 `get_font()`）。
3. **HUD 布局定稿（48px 高）**：左「剩余敌人图标 + 数字」、中「分数」、右「生命图标 ×N + 关卡号」；给出每个元素的 x/y 与图标尺寸（16×16）。
4. **标题界面布局**：一句话定位（20px，两行居中）→ 模式列表（3 项，↑↓选择、Enter 确认）→ 底部操作提示。给出线框尺寸。
5. **暂停界面**：半透明遮罩 + 「继续 / 重新开始 / 返回标题」。
6. **结算界面**：胜利（黄色「胜 利」+ 分数 + 用时 + 击杀数 + 「按 Enter 下一关」）、失败（红色「游戏结束」+ 原因区分「生命耗尽 / 基地被毁」+ 重开）。**明确失败原因必须区分显示**，这是评委最容易注意到的细节。
7. **反馈规格**：击中闪白 2 帧、爆炸 3 帧、屏幕震动 4px/6 帧、拾取道具闪光环、无敌期 8 帧闪烁。
8. **中文/英文回退规则**：沿用现有 `_TEXTS` + `_detect_cjk_font()` 机制，不引入字体文件。

## 5. 关键假设与决策（Assumptions & Decisions）

1. 项目定位＝**作品集/答辩**，评价标准是「设计自洽 + 亮点可讲 + 成品完整」，因此优先做"能看见、能讲清"的东西，不追求系统数量。
2. 本轮只交付两份文档，**不改任何代码**；代码改动全部列入 M1~M4，作为后续独立轮次执行。
3. 内容规模锁定为 **3 关 / 2 敌型 / 3 道具**，这是需求文档「应该有」的最小实现，也是答辩能讲完的上限；不引入第 3 种敌型、不做 Boss、不做商店。
4. AI 亮点按真实数据讲（会杀不会通关），不虚构；M4 是"如果时间允许"的加分项，不是必做。
5. 音效与美术继续坚持"全代码生成、零外部素材"，这本身就是一个可讲的工程亮点。
6. 文档语言为中文，术语保留英文缩写（DQN/HUD/FPS），便于答辩时与代码对照。
