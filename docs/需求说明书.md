# 《AI 坦克大战》需求说明书

版本 v1.0 ｜ 更新日期 2026-11-12 ｜ 对应代码版本：`main` 分支 `9f58b70`

## 1. 项目背景与目标

### 1.1 背景

课程要求完成一个能够体现人工智能技术的可运行项目。常见选题多为分类/预测类模型，缺少可交互的完整产品形态。本项目把强化学习放进一个可直接游玩的复古像素坦克游戏里：玩家与"自己训练出来的 AI"在同一张地图上对战，训练、评估、观战、游玩共用同一套规则与环境。

### 1.2 目标

| 编号 | 目标 | 可验证方式 |
|---|---|---|
| G1 | 做出可完整游玩的对战游戏 | 从标题进入对局，能胜利或失败并结算、重开 |
| G2 | 训练出具备真实行为的 Double DQN 对手 | `models/train_log.csv` 有击杀记录；`evaluate.py` 可复现胜率 |
| G3 | 训练与游玩共用同一环境，零外部素材 | 无网络、无图片音频文件也能运行；`python -m compileall` 通过 |

### 1.3 技术栈

Python 3.8+、Pygame 2.6.1、NumPy、PyTorch。渲染、精灵、音效全部由代码生成。

## 2. 目标用户与使用场景

| 用户 | 场景 | 关注点 |
|---|---|---|
| 学生本人 | 开发、调参、答辩演示 | 训练曲线可解释、规则可讲清 |
| 答辩/评审 | 现场试玩 1~2 局 | 上手快、界面反馈明确、不依赖网络 |
| 独立玩家 | 挑战 AI、刷分数 | 操作手感、AI 强度、重开成本 |

## 3. 功能需求

优先级：P0 必须、P1 应该、P2 可选。

### 3.1 标题与菜单

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR-01 | 标题主菜单 | 五个按钮：对战 / 排位 / 自定义 / 坦克营地 / 设置；另有地图卡片与出战配置行 | P0 |
| FR-02 | 键鼠双操作 | W/S 或上下键切换，Enter 确认，左键点击可直达 | P0 |
| FR-03 | 出战配置 | A/D 切换坦克型号（轻骑/标准/重装）、人数（2~4）、地图（随机/三张预设） | P0 |
| FR-04 | 坦克营地 | 大图预览三款坦克属性，Enter 选用 | P1 |
| FR-05 | 设置页 | 八行：音乐、音效、总音量、音效音量、人数、对手名字、键位、返回 | P0 |
| FR-06 | 名片与键位 | 输入玩家名字、选择头像、自定义七个按键；写入 `prefs.json` | P1 |
| FR-07 | 双语文案 | 系统有中文字体时显示中文，否则回退英文 | P1 |

### 3.2 对局模式

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR-08 | 对战 | 纯竞技场：无基地、无道具、无毒圈，全灭对手获胜 | P0 |
| FR-09 | 排位 | 完整规则：毒圈收缩 + 道具刷新 + 击杀播报 | P0 |
| FR-10 | 自定义 | 跑图练习：静止靶子，全灭后自动重建 | P1 |
| FR-11 | AI 观战 | `play_ai.py` 让四个位置都由模型驱动，ε=0 | P1 |

### 3.3 战斗规则

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR-12 | 1 命制 | 每方 1 条命、100 HP，血尽立即淘汰，无复活 | P0 |
| FR-13 | 坦克型号 | 轻骑普攻 20% 二连发、标准 34%、重装 40% 扇形；技能分别为疾冲、穿甲 50%、冲击波 60% | P0 |
| FR-14 | 弹匣与换弹 | 轻骑 3 发 / 标准 4 发 / 重装 2 发，打空自动换弹 1~2s | P0 |
| FR-15 | 受击反馈 | 扣血后 0.5s 无敌并沿弹道击退 4px | P1 |
| FR-16 | 毒圈 | 6s 安全期后每 3s 缩 1 圈，半径 8→0；圈外每 1.5s 扣 34（无视护盾） | P0 |
| FR-17 | 道具 | 加血 34 / 火力冷却 ×0.7 / 护盾 5s / 地雷 34；每 10s 刷新，场上最多 2 个，15s 消失 | P0 |
| FR-18 | 视野 | 玩家与 AI 同为 6 格圆形视野，视野外不显示敌人、子弹、道具 | P0 |
| FR-19 | 草地隐身 | 草内坦克能看见外面，外面看不见草内 | P0 |
| FR-20 | HUD | 血条、弹匣、技能冷却、剩余对手、毒圈倒计时、击杀播报 | P0 |
| FR-21 | 暂停与结算 | Esc 暂停；胜利/失败页展示分数、击杀、用时，Enter 重开、Esc 返回 | P0 |

### 3.4 AI 与数据

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR-22 | DQN 对手 | 3 个对手由 Double DQN 驱动，每 4 帧决策一次，可释放技能 | P0 |
| FR-23 | 训练入口 | `python train.py --episodes N` 自博弈训练，写日志、定期保存与评估 | P0 |
| FR-24 | 评估入口 | `python evaluate.py --episodes N --seed S` 贪心评估，结果可复现 | P0 |
| FR-25 | 训练曲线 | `python plot_curve.py` 生成 `models/train_curve.png` | P2 |
| FR-26 | 试玩日志 | 人类对局写入 `playtest/sessions.csv` | P2 |

## 4. 非功能需求

| 编号 | 需求 | 指标 | 优先级 |
|---|---|---|---|
| NFR-01 | 帧率 | 60 FPS，逻辑分辨率 416×464 整数放大 2 倍 | P0 |
| NFR-02 | 启动不卡顿 | 点击对战/排位后主线程立即响应，模型在后台加载 | P0 |
| NFR-03 | 离线可运行 | 不访问网络，不依赖外部图片/音频文件 | P0 |
| NFR-04 | 无声卡可运行 | 初始化失败时自动静音，不影响游戏 | P1 |
| NFR-05 | 兼容性 | Python 3.8+，Windows 优先，无 GPU 时纯 CPU 推理 | P1 |
| NFR-06 | 可复现 | 固定 seed 下评估结果一致 | P1 |
| NFR-07 | 内存 | 人类对局不分配训练回放池，避免约 300MB 无用内存 | P1 |

## 5. 范围与非目标

明确不做：联机对战、关卡战役、资源/商店系统、手机端适配、云存档、模型热更新。
