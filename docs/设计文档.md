# 《AI 坦克大战》设计文档

版本 v1.0 ｜ 更新日期 2026-11-12 ｜ 依据代码：`main.py`、`game/`、`ai/`

## 1. 总体架构

```
入口层
  main.py        人类游玩入口（标题 / 暂停 / 结算）
  play_ai.py     四 AI 自博弈观战
  train.py       自博弈训练
  evaluate.py    贪心评估
  plot_curve.py  训练曲线绘制
        │
核心层 game/
  core.py        状态机、输入、碰撞、对战逻辑、渲染（2936 行）
  settings.py    全部数值常量
  entities.py    坦克、子弹、道具、爆炸、粒子
  level.py       17×17 地图生成与出生点
  env.py         VersusEnv 强化学习环境 + 384 维状态构造
  sprites.py     字符矩阵像素精灵
  audio.py       numpy 合成音效与音量链
  avatars.py     头像池与缩放缓存
  prefs.py       prefs.json 读写与校验
  ime.py         输入法禁用与文本输入
  playtest.py    试玩会话日志
        │
AI 层 ai/
  dqn.py         QNet / ReplayBuffer / DQNAgent
```

依赖方向单向：入口层 → 核心层 → AI 层（`env.py` 引用 `core.Game`，`dqn.py` 不反向依赖游戏）。

## 2. 状态机

```
START ──(Enter/点击 对战|排位)──► PLAYING ──(Esc)──► PAUSED
  ▲                                  │                  │
  │                                  ├──(全灭对手)──► WIN
  │                                  └──(HP 归零)───► LOSE
  │                                                     │
  └──────────(Esc)──────────────────────────────────────┘
```

| 状态 | 进入条件 | 可执行操作 |
|---|---|---|
| `START` | 启动、返回首页 | 菜单导航、进入设置/名片/键位/营地、进入对局 |
| `PLAYING` | 模型就绪后调用 `_reset_battle()` | 移动、射击、技能、暂停 |
| `PAUSED` | 游戏中按 Esc | 继续、重开、返回首页、设置；特效计时冻结 |
| `WIN` / `LOSE` | `_check_win()` 判定 | Enter 重开、Esc 返回、鼠标点击重开 |

标题层的子视图（设置、名片、键位、坦克营地）不是独立状态，由 `settings_view`、`profile_view`、`keybind_view`、`garage_view` 等标志叠加在 `START` 上，渲染与鼠标命中共用 `_row()` 布局。

模型尚未就绪时的"加载中"同样不是独立状态，由 `start_notice = "agent_loading"` 与 `_pending_ai_mode` 表示。

## 3. 核心数据结构

### 3.1 Game

| 字段 | 作用 |
|---|---|
| `state` / `frame` / `time_frames` | 状态机与计时 |
| `battle_mode` | `versus`（排位）/ `pure`（对战）/ `roam`（自定义） |
| `grid` | 17×17 地形编码二维数组 |
| `player` / `versus_foes` / `enemies` | 玩家坦克与 AI 对手 |
| `bullets` / `items` / `explosions` | 子弹、道具、爆炸 |
| `zone_radius` / `zone_timer` / `zone_tick` | 毒圈状态 |
| `announcements` / `kill_feed` | 公告与击杀播报 |
| `shake` / `rings` / `particles` / `afterimages` / `muzzles` | 打击反馈表现层 |
| `dqn_agent` / `_agent_status` / `_agent_queue` / `_agent_thread` / `_pending_ai_mode` | AI 模型加载与推理 |

### 3.2 实体

- `PlayerTank`：位置、朝向、HP、无敌计时、弹匣、换弹计时、技能冷却、型号参数。
- `Bullet`：位置、方向、速度、归属、伤害、是否穿甲。
- `Item`：种类（加血/火力/护盾/地雷）、剩余存在时间。
- `Explosion` / `PixelParticle` / `Afterimage`：纯视觉对象，不参与碰撞判定。

### 3.3 VersusEnv

包装 `Game` 提供 RL 接口：`reset()` 返回 384 维状态，`step(action, epsilon)` 返回下一状态、奖励、done、info；`set_opponents(agent)` 让三个对手共用同一份参数。

## 4. 关键流程

### 4.1 启动与后台模型预加载

```
main.py
  ├─ 设置任务栏标识与窗口图标
  ├─ 创建 Game(log_playtest=True)
  ├─ game.start_agent_preload()   ← 唯一一次，daemon 线程
  └─ 进入 60 FPS 事件循环
```

后台线程只做三件事：导入 PyTorch 与 `ai.dqn`、构造 `DQNAgent(buffer_capacity=0)`、`load(models/dqn_tank.pth)`，结果放入队列。主线程每帧 `_poll_agent_preload()` 非阻塞取结果，成功后先安装状态构造与动作解码钩子，再发布 `dqn_agent`。

### 4.2 开局

`_start_versus()` / `_start_pure()` → `_ensure_agent(mode)`：

- 模型已就绪：直接 `_reset_battle()` 并进入 `PLAYING`。
- 模型加载中：记录 `_pending_ai_mode`，显示加载页，等待轮询自动进入。
- 模型缺失/损坏：显示对应提示，不进入对局。

`_reset_battle()` 负责：抽取地图、生成互不相邻出生点、创建玩家与 3 个 AI、清空子弹/道具/特效、重置毒圈与道具计时、给全体 2 秒出生无敌。

### 4.3 单帧更新顺序（`Game.update()`）

1. `_poll_agent_preload()` 接收模型加载结果。
2. 暂停时冻结特效计时，非 `PLAYING` 直接返回。
3. 递减公告与击杀播报存活时间。
4. 玩家计时器、二连发补弹、移动、开火。
5. AI 对手计时器与决策（每 4 帧一次，跑图模式不动）。
6. 排位模式：刷新道具、推进毒圈。
7. 子弹移动与命中判定。
8. 草地进出的视觉环。
9. 爆炸与粒子更新。
10. 胜负判定；跑图模式靶子全灭后重建。

### 4.4 结算与重开

`_check_win()` 判定全灭或玩家 HP 归零后切到 `WIN`/`LOSE`，结算页展示分数、击杀、用时、排名；Enter 重新调用开局流程，模型已缓存，不重复加载。

## 5. 渲染与资源

- 逻辑分辨率 416×464（17×17 格 ×24px + HUD 56px），窗口 832×928 整数 2 倍放大，最近邻取样保持像素锐利。
- 精灵由 `sprites.py` 的字符矩阵在代码中生成并单例缓存，不依赖外部图片；`assets/tanks/` 可选覆盖贴皮，缺图自动回退。
- 字体按微软雅黑 → 黑体 → 宋体 → 楷体顺序探测，均不存在时回退英文文案。
- 音效由 `audio.py` 用 numpy 合成波形，每个 Channel 独立设置音量，最终音量 = 基础增益 × 总音量 × 音效音量 × 事件音量；无音频设备自动静音。
- 打击反馈：屏幕震动（带裁剪防止 HUD 抖动）、闪光环、粒子、残影、枪口火焰，使用独立随机源避免影响地图与道具随机序列。

## 6. 配置与持久化

| 文件 | 内容 | 写入时机 |
|---|---|---|
| `prefs.json` | 音乐/音效开关、总音量、音效音量、人数、坦克、地图、对手名字显示、键位、玩家名、头像 | 设置变更、名片确认、退出时 |
| `playtest/sessions.csv` | 每局会话 ID、胜负、失败原因、分数、击杀、剩余命、用时 | 每局开始与结束 |
| `models/dqn_tank.pth` | 在线网络权重 | 训练每 200 局与结束时 |
| `models/train_log.csv` | 每局奖励、击杀、胜负、ε、步数 | 每局追加 |
| `models/eval_log.csv` | 每 200 局评估胜率、击杀、奖励、步数 | 评估后追加 |

旧配置缺字段时自动补默认值，音量等数值做类型与范围校验。

## 7. 性能设计

| 措施 | 效果 |
|---|---|
| 模型后台预加载 | 首次点击不再阻塞主线程（原同步导入 PyTorch 约 2.4s） |
| 进程内模型缓存 | 重开、返回标题再进入无需重复加载 |
| 推理用零容量回放池 | 真人局不分配约 308MB 训练数组 |
| 精灵/头像/字体缓存 | 避免每帧重建 Surface |
| 逻辑分辨率 + 整数放大 | 渲染与碰撞都在小画布完成 |
| 粒子上限与按帧清理 | 特效不无限增长 |

## 8. 非功能约束

- 单线程主循环 + 一个后台加载线程，后台线程不触碰 Pygame 与游戏状态。
- 训练/评估使用 `SDL_VIDEODRIVER=dummy` 无头运行。
- 训练、评估、RL 环境不会自动启动后台预加载，避免 headless 环境意外加载模型。
