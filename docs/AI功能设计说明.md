# 《AI 坦克大战》AI 功能设计说明

版本 v1.0 ｜ 更新日期 2026-11-12 ｜ 数据来源：`game/env.py`、`game/settings.py`、`ai/dqn.py`、`train.py`

## 1. 设计目标与思路

三个待解决的问题：

1. **不用画面做输入**。像素画面送入 CNN 需要大量样本、训练慢且难解释。本项目改用结构化状态向量，把"我、对手、子弹、地图、道具、毒圈"直接编码成数值，CPU 也能在可接受时间内完成训练。
2. **对手不是脚本**。AI 由 Double DQN 训练得到，行为随训练变化，答辩时可现场重训、现场对比。
3. **训练与游玩同源**。训练环境 `VersusEnv` 包装的就是游戏里的 `Game`，观测、动作、奖励与真人局完全一致，不存在"训练一套、实机另一套"。

## 2. 状态空间：384 维

状态向量由 `game/env.py` 的 `build_foe_state()` 构造，每个 AI 都以自己视角生成一份，分段如下：

| 区间 | 维度 | 内容 | 归一化 |
|---|---|---|---|
| 0–7 | 8 | 自身：x、y、朝向 one-hot(4)、存活、无敌计时 | 坐标 ÷ 场地尺寸，计时 ÷ 120 帧 |
| 8 | 1 | 基地槽，恒 0 | 布局兼容保留 |
| 9–36 | 28 | 对手 4 槽 × 7：x、y、朝向 one-hot(4)、存活 | 同上 |
| 37–76 | 40 | 子弹 8 槽 × 5：x、y、速度方向 vx/vy、归属（自己 +1 / 他人 −1） | 坐标 ÷ 屏幕尺寸 |
| 77–365 | 289 | 地图 17×17 逐格地形编码 | ÷5 |
| 366–377 | 12 | 道具 3 槽 × 4：x、y、种类（÷3）、有效标志 | 按剩余存在时间降序取前 3 |
| 378–383 | 6 | 元信息：存活对手比例、自身血量比例、毒圈半径比例、收缩倒计时比例、离安全区边缘有符号距离、离中心比例 | 0~1，距离可为负 |

**合计 8+1+28+40+289+12+6 = 384。**

视野与隐身规则同时作用于观测：

- 视野半径 6 格（`VIEW_RADIUS_TILES=6`），视野外的对手、子弹、道具不写入状态。
- 观察者不在草地时，草地里的对手从对手槽隐去；观察者在草地时可见全部对手。
- 这两个规则与玩家渲染完全一致，AI 不会"透视"。

## 3. 动作空间：10 个离散动作

| 动作号 | 含义 |
|---|---|
| 1–4 | 向上/下/左/右移动 |
| 5–8 | 对应方向移动并开火 |
| 9 | 原地开火 |
| 0 | 静止 |

每 4 帧（`FRAME_SKIP=4`，约 15 次/秒）决策一次，决策之间重复执行同一动作。技能不由动作空间控制：AI 按规则在冷却完成且目标进入技能范围时自动释放，避免动作空间与人类操作不对等。

## 4. 网络结构

```
输入 384 → Linear 256 → ReLU → Linear 256 → ReLU → Linear 10（每个动作的 Q 值）
```

实现位于 `ai/dqn.py` 的 `QNet`。在线网络与目标网络结构相同，各约 17 万参数，整模型文件约 650KB。

## 5. 算法：Double DQN

- **选动作**：ε-greedy。训练时按当前 ε 随机探索，否则取在线网络 Q 值最大的动作；评估与真人对局时 ε=0。
- **算目标**：由在线网络选出下一状态的动作，再由目标网络给出该动作的 Q 值：
  `target = r + γ · Q_target(s', argmax_a Q_online(s', a))`，抑制普通 DQN 的高估。
- **损失**：SmoothL1（Huber），对异常奖励更稳。
- **目标网络同步**：每 500 次梯度更新硬拷贝一次在线网络参数。
- **经验回放**：定长循环队列 200,000 条，随机采样 batch 128。

训练超参以 `train.py` 参数为准：

| 参数 | 值 |
|---|---|
| 学习率 | 5e-4（Adam） |
| 折扣 γ | 0.99 |
| 回放池 | 200,000 |
| batch | 128 |
| 每几次决策更新一次 | 4 |
| ε 起止 | 1.0 → 0.05 |
| ε 线性衰减步数 | 250,000 |
| target 同步间隔 | 500 次更新 |
| 默认训练局数 | 5000 |

## 6. 奖励设计

奖励定义在 `game/settings.py` 的 `VS_R_*`：

| 事件 | 奖励 | 设计意图 |
|---|---|---|
| 淘汰一个对手 | +500 | 主目标 |
| 自己被淘汰 | −500 | 终局强信号 |
| 每个决策步 | −0.2 | 轻微时间压力，避免无意义拖延 |
| 本决策位移 ≥3px | +0.2 | 鼓励移动 |
| 几乎没移动 | −0.2 | 反蹲点 |
| 中心格在安全区外 | −2.0 | 主动躲毒圈 |
| 距安全区边界 ≤1 格 | −0.5 | 提前撤离，而不是贴圈 |
| 每次开火 | −1.0 | 抑制无意义扫射 |
| 每次有效命中 | +4.0 | 按命中次数计，不按伤害缩放 |

奖励与游戏分数是两套独立数值，改游戏分数不影响训练。

## 7. 自博弈训练管线

```
VersusEnv.reset()
   ↓ 384 维状态
DQNAgent.act(state, ε) → 动作
   ↓
VersusEnv.step(action, ε)  ← 3 个对手与学习者共用同一份参数
   ↓ 下一状态、奖励、done、info
store → 每 4 步 learn() → 定期同步 target
   ↓
每 200 局：保存模型、跑 20 局贪心评估、写 eval_log.csv
```

- 训练默认无头运行（`SDL_VIDEODRIVER=dummy`），单进程 CPU。
- 日志：`models/train_log.csv`（每局奖励/击杀/胜负/ε/步数）、`models/eval_log.csv`（每 200 局评估）。
- 模型：`models/dqn_tank.pth`，旧版本归档在 `models/legacy/`。
- 支持 `--resume` 续训；加载时对首层输入维度变宽的旧模型做宽容迁移（旧权重复制到前 N 列，新增列保持初始化）。

## 8. 推理与加载优化

| 场景 | 做法 |
|---|---|
| 训练 | 完整回放池 200,000，正常学习 |
| 真人对局 | 后台线程预加载模型，主线程每帧非阻塞取结果 |
| 回放池 | 真人局用 `buffer_capacity=0`，不分配约 308MB 的训练数组 |
| 加载中点击 | 显示"AI 模型加载中…"，完成后自动进入；Esc 取消进入但继续后台加载 |
| 模型缺失/损坏 | 分别提示"未找到模型"和"加载失败"，不会卡在加载页 |
| 重复进入 | 模型在进程内缓存，重开与返回标题再进入不再重复加载 |

## 9. 实测结果

训练累计 5000 局自博弈，最终 ε=0.05。`models/eval_log.csv` 每 200 局评估一次（贪心、20 局、自博弈镜像）：

| 训练局数 | 评估胜率 | 平均击杀 | 平均奖励 |
|---|---|---|---|
| 2000 | 35% | 1.20 | 218.6 |
| 3000 | 45% | 1.40 | 393.9 |
| 4000 | 40% | 1.15 | 256.4 |
| 4600 | 45% | 1.45 | 442.2 |
| 5000 | 20% | 0.60 | −156.5 |

4 人镜像自博弈的理论胜率上限约 25%，训练中段多次达到或接近该水平，末段出现回落，属于自博弈无快照池时的典型震荡，如实记录。

复现命令：

```powershell
python evaluate.py --episodes 20 --seed 1
python plot_curve.py
```

## 10. 局限与改进方向

1. **无快照池**：对手就是当前参数本身，策略会左右互搏式震荡，评估胜率不保证单调上升。改进：维护历史模型池，每 N 局随机抽取一个作为对手。
2. **评估样本小**：20 局方差大，0.20 与 0.45 的差异可能主要来自随机性。改进：评估 50~100 局并给出置信区间。
3. **奖励稀疏**：击杀与阵亡是事件级信号，走位质量没有直接梯度，靠移动/蹲点/开火惩罚间接塑形。
4. **模型与规则不完全同源**：当前模型经历过血量与地图尺寸调整，部分旧权重需要重训才能发挥最优水平。改进：规则冻结后完整重跑 5000 局。
5. **单一对手类型**：训练环境固定标准型坦克，实机对手随机三款型号，存在分布差异。改进：训练时随机化对手型号。
