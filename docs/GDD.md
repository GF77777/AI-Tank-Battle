## 1. 一句话定位

**一款复古像素坦克大战：玩家在竞技场里与 3 个「自己训练出来的 AI」大混战——玩法、实现、自博弈训练全链路可讲。**

| 项 | 内容 |
|---|---|
| 类型 | 俯视角 2D 射击 / 单机 AI 对战（FFA 1v3） |
| 平台 | Windows 桌面（Python 3.12 + Pygame，固定窗口 832×928） |
| 操作 | 键盘：方向键/WASD 移动，J 普攻，K 立即释放技能，Esc 暂停，Enter 确认 |
| 单局时长 | 30 秒～2 分钟（1 命制 ×100 HP，道具加速战局终结） |
| 难度定位 | 简单偏休闲：100 HP、受击 0.5s 无敌、出生保护 2 秒、道具可回血、对称公平竞技场 |
| 核心差异 | 不是"又多一个坦克大战"，而是"对手就是我自己训出来的模型"——自博弈训练闭环可讲可查 |

## 2. 目标玩家与体验目标

**目标玩家**：喜欢 FC 怀旧手感、单局时间短、愿意反复冲分的玩家；以及对强化学习有好奇心的技术观众（答辩评委、面试官）。

**三条核心体验（按优先级）**

1. **一气呵成的走位射击**——2px/帧的坦克、5px/帧的子弹、差异化百分比伤害与 0.5 秒受击无敌，每次命中都有明确反馈。
2. **大混战的读局博弈**——FFA 下 AI 互相攻击，"先打谁、躲哪边"是持续的小决策；击杀与被杀都有明确反馈。
3. **"这是我训出来的 AI"**——3 个对手由同一份 DQN 参数驱动，它的强与弱、训练曲线、评估基线都有数据可讲。

**情绪曲线**：开局试探（四角出生、互相接近）→ 中段交火（砖墙被打穿、战线收缩）→ 残局紧张（命数见底、1v1 决斗）→ 结算释放（胜负 + 击杀数）。

---

## 3. 核心循环

```
标题 → 对战模式 → 竞技场开局 → 走位/普攻/技能 → 有效命中（+100）/ 被击中（按来源扣 HP）
       ↑                                    │
       │                                    ▼
       │                        命尽淘汰（自己或对手）
       │                                    │
       └──── Enter 重开 ◄── 结算（胜=全灭对手 / 负=命尽）
```

**局内小循环（约 10 秒一个节奏）**：观察三个 AI 的位置与交火对象 → 选掩体/绕侧 → 打砖墙造射击线 → 收残血或用技能进场。

**重玩动力（不依赖存档）**：①想赢一次自己训的 AI ②冲单局击杀数 ③三辆坦克手感差异各试一遍。

## 4. 操作与手感参数（全部取自 `game/settings.py`）

| 参数 | 值 | 说明 |
|---|---|---|
| 坦克速度 | 标准 2.0 / 轻骑 2.6 / 重装 1.6 px/帧 | `TANK_TYPES` |
| 子弹速度 | 5.0 px/帧 | `BULLET_SPEED` |
| 射速冷却 | 21 帧（重装 26） | `PLAYER_FIRE_COOLDOWN` / 型号配置 |
| 弹上限 | 2 发（轻骑/标准） | `PLAYER_MAX_BULLETS` |
| 每方生命 | 1 | `VERSUS_LIVES=1`，1 条命 100 HP，血尽即淘汰，玩家与 AI 共用同一常量 |
| 出生保护 | 120 帧（2s） | `RESPAWN_INVINCIBLE`（1 命制下复用为开局无敌） |
| 转向对齐 | 4 px 网格 | `ALIGN_GRID`，保证能穿单格通道 |
| 坦克 / 子弹尺寸 | 28×28 / 6×6 px | `TANK_SIZE` / `BULLET_SIZE` |
| 帧率 / 决策 | 60 FPS / 每 4 帧一次 | `FPS` / `FRAME_SKIP` |

**手感设计意图**

* 转向时自动对齐 4px 网格：避免"卡在墙角进不去通道"的挫败感。
* 每命 100 HP：不同攻击扣除不同百分比，受击短暂无敌，既有明确反馈，又不会被一轮子弹瞬秒。
* 1 命制 + 出生 2 秒保护：被淘汰即出局，容错靠加血道具与护盾道具补，节奏更紧张。

### 4.1 玩家坦克型号（出战配置 3 选 1）

| 型号 | 速度 | 射速冷却 | 开火方式 | 普攻伤害 | 技能冷却 | K 技能（瞬发） | 定位与设计意图 |
|---|---|---|---|---|---|---|---|
| 轻骑（蓝黑·科技蓝条） | **2.6**（+30%） | 21 | **自动二连发**（间隔 6 帧），射程 2.5 格 | **20** | 42 帧恢复 1 次 | **冲锋疾冲（0 伤害）**：沿朝向疾冲 2 格，最多储存 2 次；穿过坦克与钢板、撞碎砖墙，危险终点回退 | 高机动持续输出，5 次有效普攻淘汰 |
| 标准（沙漠黄·红条纹） | 2.0 | 21 | 单发，射程 3.5 格 | **34** | 42 帧（0.70s） | **穿甲弹（50 伤害）**：沿车头直线不追踪，穿砖穿人、被钢板挡 | 3 次普攻或 2 次穿甲淘汰；RL 固定型号 |
| 重装（军绿·铆钉） | **1.6**（-20%） | **26** | **扇形冲击**，半径 2 格、半角 30° | **40** | 42 帧（0.70s） | **全向冲击波（60 伤害）**：360° 范围伤害，半径同扇形 | 近身高爆发，3 次普攻或 2 次冲击波淘汰 |

**通用规则**：所有坦克统一 100 HP，表内伤害整数同时对应百分比。J 普攻与 K 技能分别计算冷却，互不重置；穿甲与冲击波冷却为 42 帧，轻骑疾冲最多储存 2 次、每 42 帧恢复 1 次。右下角技能环显示可用状态与恢复秒数，轻骑同时显示剩余次数。AI 技能由规则瞬发，DQN 动作空间不含独立技能动作。

**设计决策**：三辆共用同一套碰撞、100 HP 与受击无敌规则——build 差异来自伤害、开火方式、技能与手感参数，不引入技能树。

### 4.2 对战模式规则（核心玩法）

| 项 | 规则 |
|---|---|
| 地图 | 17×17 四向对称竞技场 ×3 张预设（折角回廊 / 十字阵 / 放射阵），每局随机抽取（`load_versus_map()`）；无基地（公平） |
| 出生 | 2 人局对角、3 人局三角、4 人局四角（`SPAWNS_BY_COUNT`），出生朝向场地中心，出生无敌 2 秒 |
| AI 对手 | 3 个 AI 随机三款坦克型号（头顶红色字母 A/B/C 区分），由 `models/dqn_tank.pth` 驱动，共享一个 agent 实例；决策节奏与训练一致（每 4 帧一次，ε=0 纯贪心） |
| 状态视角 | 每方用第一人称视角构造 384 维状态：自身占自身槽、其余 3 方占对手槽、子弹按 owner 区分敌我、基地槽恒 0、道具 3 槽全场可见（视野外隐藏） |
| 生命 | 每方 **1 条命**（`VERSUS_LIVES=1`）；血量归零即淘汰，**无复活** |
| 血量 | 每命 100 HP（`VERSUS_HP`）；按攻击来源扣除对应数值，随后 0.5s 无敌（`HIT_INVINCIBLE`）并沿子弹方向击退 4px（`HIT_KNOCKBACK`） |
| 道具 | 加血（+34 HP）/ 火力（冷却 ×0.7 叠 2 层）/ 护盾（无敌 5s）/ 地雷（造成 34 伤害，无敌期免疫）；每 10s 随机空格刷 1 个（场上 ≤2），淘汰对手死亡格掉落 1 个（无地雷，≤1）；15s 未拾取消失；玩家与 AI 均可拾取（`ITEM_*` 常量族） |
| 胜负 | 全部 AI 被淘汰 → 胜利；玩家被淘汰 → 失败。分数=每次有效命中 ×100，Enter 重开一局 |
| 子弹 | 按 owner 判定归属：任意两发不同 owner 的子弹相撞互消；命中任何非发射者坦克（无敌期吸收）；穿甲弹仍可穿人 |

**设计意图**：把"训出来的 AI"从观战对象变成可对战的对手；FFA 规则下 AI 互耗让战局可读、节奏可控；对称地图与统一生命数保证"输了只能怪自己"。

## 6. AI 对手（DQN 驱动）

竞技场没有脚本敌人：3 个对手就是训练产物本身。行为边界：

* 每 4 帧决策一次，动作空间 10（不动 / 四向移动 / 四向移动+射击 / 原地射击），与学习者完全对等。
* 技能由游戏规则触发，DQN 动作空间不含独立技能动作；会拾取道具（道具在状态向量中全场可见）。
* 观战需求由 `play_ai.py` 承接：玩家侧也由同一模型驱动，即 4 个 AI 自博弈互殴。
* 主程序创建标题界面后启动唯一的 daemon 后台线程加载模型；worker 不接触 Pygame 或游戏状态，主线程通过非阻塞队列统一安装 Agent 与决策钩子。加载完成后模型缓存复用，重开和再次进入不重复读取。
* 真人游戏仅以 `buffer_capacity=0` 创建推理 Agent，不分配默认约 309 MB 的训练回放数组；训练默认容量、网络结构、384 维观测、奖励和模型文件均不变，`train.py` / `evaluate.py` / `VersusEnv` 不会自动启动预加载。

## 8. AI 系统说明（答辩核心章节）

### 8.1 观测与动作

| 项 | 设计 | 依据 |
|---|---|---|
| 观测量 | 384 维结构化状态向量 | 自身 8 + 基地 1（恒 0，布局兼容）+ 对手 4×7=28 + 子弹 8×5=40 + 地图 17×17=289 + 道具 3×4=12（位置/种类/有效）+ 元信息 6（存活对手比例、自身血量比例、毒圈半径、收缩倒计时、离安全区边缘有符号距离、离中心比例） |
| 草地视野 | 观察者不在草地时，草地里的对手从对手槽隐去；观察者在草地时可见全部对手 | 单向可见（藏身者看得见外面，外面看不见藏身者） |
| 为什么不用画面 | 结构化状态收敛快、可解释、CPU 可训 | |
| 动作 | 10 个离散动作 | 人类可同时按方向键+J，普攻动作空间必须对等 |
| 决策频率 | 每 4 帧决策一次（≈15 次/秒），决策间重复执行 | 单局上限 3000 决策步 |

### 8.2 算法与自博弈训练管线（v3.0）

* 网络：MLP 384 → 256 → 256 → 10，ReLU。
* 算法：Double DQN（online 选动作、target 估值），target 每 500 次梯度更新硬同步。
* 超参：γ=0.99，Adam lr=5e-4，batch 128，回放池 200,000，Huber loss，每 4 个决策步更新一次。
* 探索：ε 1.0 → 0.05，线性衰减 250,000 决策步（自博弈需持续探索）。
* **自博弈 FFA**：学习者（玩家出生位）与 3 个对手**共用同一份 DQN 参数**；对手每一步的探索率 ε 与学习者当前 ε 相同（`env.step(action, epsilon=eps)`）。只学学习者视角的 transition——标准自博弈简化，对手火力随学习者变强而变强。
* 奖励（`settings.py` 的 `VS_R_*`）：淘汰对手 +500、被淘汰 −500、每决策步 −0.2、移动 +0.2、蹲点 −0.2、圈外 −2.0、贴圈 −0.5、开火 −1.0、有效命中 +4.0。
* 地图随机化：每局从 3 张四向对称预设图随机抽取（域随机化），地图本就编码在状态 289 维中。

### 8.3 实测结果（真实数据，禁止美化）

| 指标 | 数值 | 来源 |
|---|---|---|
| 训练局数 | 5000 局自博弈 | `models/train_log.csv` |
| 最终 ε | 0.05 | 同上 |
| 贪心评估胜率 | 20%（最近一次，20 局，对手同模型 ε=0） | `models/eval_log.csv` |
| 贪心平均击杀 | 0.60 | 同上 |
| 贪心平均奖励 | −156.5 | 同上 |
| 训练中段最佳评估 | 4600 局时胜率 45%、场均击杀 1.45 | 同上 |

> 评估每 200 局记录一次，胜率在 5%~45% 间波动；4 人镜像 FFA 理论上限约 25%，中段多次接近，末段回落属自博弈典型震荡。
> 旧闯关时代模型归档在 `models/legacy/dqn_tank_campaign.pth`。

### 8.4 已知局限（必须主动讲）

1. **自博弈无快照池**：对手就是当前参数本身，策略可能"左右互搏式震荡"，不保证单调变强。
2. **奖励稀疏在中间尺度**：击杀/阵亡是事件级信号，走位质量没有直接梯度；靠 −0.2/步的时间惩罚兜底。
3. **评估噪声**：20 局样本下胜率/击杀会波动，更稳的结论需要 50+ 局。
4. **模型与最新规则不完全同源**：`models/dqn_tank.pth` 已按 384 维、1 命 100 HP 规则训练 5000 局，但若继续调整血量、伤害或地图，需要重跑 `python train.py --episodes 5000` 才能保持最佳表现。

## 9. 美术与音效基调

* **风格**：FC 8-bit 复古像素，全部精灵由 `sprites.py` 字符串矩阵在代码里生成，零外部素材。
* **调色板**：背景黑 `#000000`、HUD 深灰 `#181820`、玩家黄 `#F0C83C`、危险红 `#DC3228`、成功绿 `#50C850`、钢板灰、砖红棕、水蓝、林深绿。
* **动画**：坦克 4 朝向、普通命中 14×14 三帧爆炸（12 帧）、淘汰 30×30 三帧爆炸（24 帧）；出生/受击/护盾无敌期间坦克常显，29×29 青蓝护盾环以 20 帧周期呼吸，最后 12 帧仅环体提示闪烁。
* **战斗特效**：代码生成四方向枪口火焰、短尾迹、火花、砖屑、钢火、拾取环和毒圈粒子；轻骑每 8px 留青蓝残影，标准穿甲强化白黄炮口与尾迹，重装采用分段扇形双弧与延迟双环冲击波。所有对象仅表现层，无碰撞、无伤害。
* **表现约束**：火花/尾迹/碎屑共用 240 粒子上限，残影上限 12，暂停冻结、重开清空；视觉随机只使用独立 `fx_rng`，不得消耗全局随机序列。护盾环使用预生成帧、不消耗视觉随机，并同样遵守暂停冻结与草地/迷雾遮挡。特效不加入 `build_foe_state()`，RL 384 维观测、奖励与模型接口保持不变。
* **坦克精灵**：8 通道调色板（B 车身/D 暗部描边/H 高光/A 装饰/T 履带/W 负重轮亮纹/L 炮管），三型号玩家坦克轮廓差异化（轻骑窄身、标准车尾天线、重装宽身+炮口制退器+铆钉），AI 对手用简化无高光版拉开识别度 + 头顶红色字母 tag。
* **音效**（全部代码合成）：轻骑/标准/重装分别使用 55/85/130ms 分层开火声，普通中弹为 90ms 短促金属冲击，淘汰为 320ms 低频爆燃；保留旧射击声供疾冲、旧爆炸声供冲击波与毒圈使用，拾取及胜负音效不变。噪声使用固定局部随机种子，播放音量按 Channel 隔离，无音频设备时静音降级。设置页提供总音量与音效音量，均为 0～100%、默认 100%；Channel 最终音量为 `0.45 × 总音量 × 音效音量 × 事件系数`，两项百分比按 0～1 参与计算并写入 `prefs.json`，任一调至 0% 后后续播放静音。

**扩展规则（新内容必须遵守）**

* 新视觉识别靠"地图结构"而非新贴图；新精灵一律用字符矩阵绘制：坦克 14×14（scale 2，四方向旋转生成）、地形 16×16；每行长度必须断言校验。
* 可选坦克贴皮：`assets/tanks/{scout|standard|heavy|enemy}.png`，28×28、朝上、透明底；存在即用图片，缺失回退代码矩阵。

## 10. UI 概要

界面清单、布局坐标、字号见 [UI 设计规范](./UI设计规范.md)。GDD 只固定三条原则：

1. **任何界面都要让人 3 秒内知道下一步按什么。**
2. **AI 必须在界面上可见**：标题底部常驻「AI 策略：Double DQN 模型」，对手头顶有字母 tag。
3. **结算只分胜负**：对战没有"通关"，胜利=全灭对手，失败=命尽，结算给分数/用时/击杀三件套。

**状态流转图**

```
启动 → START（标题：对战 / 排位 / 自定义 / 坦克营地 / 设置 + 地图卡片）
        ├─ 对战 → PLAYING ⇄ PAUSED（Esc）
        │              ├─ 全灭 AI → WIN → Enter 重开
        │              └─ 命尽 → LOSE → Enter 重开
        ├─ 排位 → PLAYING（毒圈 + 道具 + 击杀播报）
        ├─ 自定义 → PLAYING（静止靶子，全灭自动重建）
        ├─ 设置 → 设置子视图（八行，Esc 返回）
        └─ 坦克营地 → 仓库子视图（Enter 选用 / Esc 返回）
```
